# 日志规范

> 2026-10-31 建立。起因：全仓 238 处裸 `System.out/err.println` 导致「日志很多但查不出问题」——
> 真正的失败原因（异常 cause）长期被执行日志淹没，甚至只打出 `null`。
> 实现见 `api/mirage-api/src/main/java/io/mirage/api/log/MirageLog.java`。

## 1. 只用 MirageLog，不裸写 System.out

```java
import io.mirage.api.log.MirageLog;

MirageLog.MIRAGE.info("发现 " + mods.size() + " 个 mod");
MirageLog.LS.warn("无人值守环境，confirm 自动降级为 crash");
MirageLog.LOADER.error("mod 扫描失败（本次按 0 个 mod 继续启动）", e);
```

`MirageLog.of("自定义标签")` 可建临时通道，但**新增通道要同步** `MirageDebug.isImportantLog`
的前缀清单，否则该通道的日志不会出现在 HUD 节选里。

现有通道：

| 通道 | 前缀 | 用途 |
|---|---|---|
| `MIRAGE` | `[Mirage]` | 加载器主通道（解析、注册表、mod 初始化、早期窗口） |
| `LS` | `[LS]` | 生命周期阶段机与周期决策 |
| `LOADER` | `[Loader]` | mod 发现与排序 |
| `MIDCACHE` | `[MidCache]` | MID 磁盘缓存 |
| `MIXIN` | `[Mirage-Mixin]` | Mixin 装配 |
| `of("<modid>")` | `[<modid>]` | mod 侧（由 `ModLoggerImpl` 自动创建） |

## 2. 带异常必须传 Throwable，禁止字符串拼接

```java
// ✗ 错：InvocationTargetException 只会打出类名，NPE 打出 "null"
System.err.println("[Mirage] 注册失败: " + e);
System.err.println("[Mirage] 事件处理错误: " + e.getMessage());

// ✓ 对：门面剥包装层、打摘要首行 + 过滤栈帧 + Caused by 链
MirageLog.MIRAGE.error("DeferredRegister 注册失败 " + id, e);
```

这是本规范最重要的一条。踩过的实例：

| 改造前的日志 | 实际原因 |
|---|---|
| `事件处理错误: null` | `IllegalStateException: Adding duplicate key 'ResourceKey[minecraft:block / mdk-example:example_block]' to registry` |
| `注册失败 expore:expore -> java.lang.reflect.InvocationTargetException` | `AssertionError: Missing intrusive holder for ResourceKey[minecraft:creative_mode_tab / expore:expore]` |

两行都因此卡了很久——原因早就抛出来了，只是被 `+ e` 吞掉。

## 3. 级别怎么选

| 级别 | 判据 | 例子 |
|---|---|---|
| `error` | 功能确实坏了，但进程还能继续 | mod 初始化失败、注册表注册失败、绘制 HUD 失败 |
| `warn` | 降级/跳过，需要人知道但不影响主流程 | 某 jar 描述符无效被跳过、mixin 织入失败退回原版、缓存写失败 |
| `info` | 正常启动的关键锚点，默认可见 | 游戏目录、发现 N 个 mod、Bootstrap、解冻 N 个注册表、flush、S6 失败汇总 |
| `debug` | 排查时才需要，**逐条**输出的诊断 | 逐 mod 发现结果、添加 mod jar、MID 缓存命中、逐条 DeferredRegister 注册、逐条 BlockState 修补、织入点提示、反射探测成功 |
| `trace` | 高频容错路径（每帧/每方块） | 绘制调用失败、`fill` 异常、字体未就绪 |

判据是「正常玩一局时，用户需不需要看这一行」。逐条循环里的输出一律 `debug`。

## 4. 冻结关键字行用 raw()

某些行是**机器可比对的契约**（历史日志 diff、冒烟脚本、文档引用），不能加级别词：

```java
MirageLog.LS.raw("[LS] stage " + stage.id() + " " + stage.name() + " start");
MirageLog.LS.raw("[LS] mode=" + mode.logName());
```

已冻结的：

- `[LS] stage <id> <name> start|done|skipped`（LifecycleScheduler，LS-Interfaces §5）
- `[LS] mode=` / `[LS] cycle=` / `[LS] sandbox-record=` / `[LS] config=` / `[LS] AG 启用集 =`
- `[LS] ParseFailPolicy=`
- `[Mirage] 来自 Mirage Launch <version>`

## 5. 阶段性失败要汇总

单个失败散落在几千行里等于没有。S6 的做法可以照搬：收集 `failures`，
阶段末尾一次性播报。

```
[Mirage] WARN  本次共 2 个 mod 初始化失败（游戏继续，相关功能可能缺失）: a(...); b(...)
```

## 6. 可以继续用 System.out 的场景

| 场景 | 原因 |
|---|---|
| `mdk/mdk-example`、`modules/*/sample` | 示例 mod 代码，展示 mod 作者的最简写法 |
| `harddecode` / `neoforge` 的 `Main.java` | 命令行分析工具，stdout 是 JSON 结果，加日志前缀会污染输出 |
| `Launcher` 的 banner 四行 | 装饰性输出，属于界面而非日志 |

除此之外，新代码不应出现裸 `System.out/err.println`。

## 7. 用户可调参数

```bash
-Dmirage.log.level=debug     # 排查启动问题（缺省 info）
-Dmirage.log.level=warn      # 只想看问题
-Dmirage.log.stack=full      # 完整堆栈（缺省 smart：前 2 帧 + 项目帧，≤16 行）
-Dmirage.log.stack=none      # 只要一行摘要
-Dmirage.log.time=true       # 带相对启动时间戳，用于看各阶段耗时
```

环境变量 `MIRAGE_LOG_LEVEL` 等价于 `-Dmirage.log.level`（系统属性优先）。

## 8. 实现注意

- **不要把 `System.out` 缓存到字段**：Launcher 在 main 早期把 stdout/stderr 换成 tee 流
  （旁路喂 HUD 日志节选），缓存引用会让之后的日志绕过 tee。
- **FATAL 不 `System.exit`**：门面只标记 + 打堆栈，退出由调用方决定
  （LS 由 `LifecycleScheduler` 统一 exit 1）。
- **不要用 `printStackTrace()`**：绕过级别与格式，stderr 上会出现没有前缀的裸栈。

## 9. 怎么验证（改门面前必跑）

`scripts/verify_logging.ps1` 是本门面的回归用例。它用 `javac` 现场编译 `MirageLog` 本体
+ 一个检查程序到临时目录，跑 5 个独立 JVM（级别在静态初始化时读取，一个进程只能测一个级别），
**不启动游戏、不依赖 gradle 产物**（`MirageLog` 只依赖 JDK 标准库，这是它放在 `api:mirage-api`
的额外好处）。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify_logging.ps1
# 失败时保留临时目录：加 -Keep
```

共 41 项断言，覆盖四条最易回归的契约：

| 契约 | 断什么 |
|---|---|
| 异常链展开 | `InvocationTargetException` / `ExceptionInInitializerError` 必须露出真实 cause 与 message；message 为空的异常只打类名，不得出现裸 `: null` |
| 级别过滤 | `warn` 时 INFO/DEBUG 不出现、WARN 仍出；`debug` 时 DEBUG 出现；`off` 时通道全静默 |
| `raw()` 保真 | `[LS] stage …` / `[LS] pipeline finished` 逐字输出、不被塞级别词、**且不受级别过滤影响** |
| 流向与对齐 | 级别词定宽 5 列；WARN 及以上走 stderr，其余走 stdout；`stack=smart` 栈帧 ≤16 行并折叠、`none` 只留摘要 |

**改了 `MirageLog` 或动了 `raw()` 的调用点，先跑它再开游戏**——纯 JVM 几秒出结果，
比启动 MC 快两个数量级。`raw()` 的判定标准也在里面：若某行确实需要保留原格式，
脚本里必须有对应断言，否则这次"冻结"是口头约定。
