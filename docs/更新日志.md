## 2026-10-18 · docs: AGENTS.md 技术注意事项追加 3 节——Mixin 管线失效诊断

- **范围**：`AGENTS.md` → "MC Mod 工程技术注意事项" 章节末尾追加。
- **背景**：排障发现之前多轮调试只验证了 mixin 配置加载成功，从未验证 `@Inject` 真正织入；测试 mixin 标记日志一次都没出现，`SharedConstants` 转换抛 `MixinTransformerError`，但 catch 里只打了 `th.toString()` 丢了完整堆栈。
- **改动点**：
  - **第 7 节 "配置加载成功 ≠ 注入生效"**：必须在测试 mixin 里放唯一标记字符串，grep 日志确认它真的出现；只看 transformer 处理日志不够；
  - **第 8 节 MixinTransformerError 诊断**：catch 块必须 `th.printStackTrace()`，`System.err.println(th)` 丢 cause 链；"An unexpected critical error was encountered" 是 Mixin 包装消息，根因在 cause；
  - **第 9 节 ASM/Mixin 转换顺序冲突**：自研 ASM 先改字节码再交给 Mixin，栈帧/调试信息不兼容会抛致命错误；两条路径对同一 MC 类二选一，不要叠加；`SharedConstants` 是典型案例。
- **验证方式**：人工通读，术语准确，来自实际排障。
- **涉及文件**：`AGENTS.md`、`docs/更新日志.md`、`docs/改动登记表.md`。

## 2026-10-18 · docs: AGENTS.md 新增"MC Mod 工程技术注意事项"章节

- **范围**：`AGENTS.md` 规则集之后新增技术踩坑档案。
- **背景**：paging-fix 调试时暴露了一组 MC Mod 工程特有的问题——fat jar 与源码不同步、`defaultRequire: 0` 让缺失 mixin 静默失效、时间线矛盾、Mixin AP 放开 protected 访问、自研 ASM vs Mixin 双路径。
- **改动点**：新增 6 节踩坑档案，用专业术语写：
  1. **fat jar 打包一致性**：改 .java 必须重打 fat jar，热替换只动单个 class；日志和源码对不上时先查 jar 构建时间；
  2. **Mixin 配置与类文件一致性**：`defaultRequire: 0` 不会崩，只是静默跳过缺失 mixin——"日志正常但功能不生效"头号原因；提交前 `jar tf` 对比 json 注册项和 jar 内 class；
  3. **双注入路径**：自研 MirageTransformer ASM（已禁用）vs SpongePowered Mixin（生效），不要同时改同一目标类；
  4. **Mixin AP 特殊性**：mixin 访问原版 protected 成员靠编译期注解处理器改写 AST，单文件 javac 报错是正常的，以 gradle build 为准；
  5. **时间线三方对齐**：git commit / fat jar 构建时间 / 日志时间戳必须对齐；
  6. **javap 查原版签名**：26.x 无混淆，`javap -p` 直接看字段权限。
- **验证方式**：人工通读，6 节均来自实际踩坑，术语准确。
- **涉及文件**：`AGENTS.md`、`docs/更新日志.md`、`docs/改动登记表.md`。

## 2026-10-17 · fix: bug #1 真修复——DeferredRegister 注册后精准清理 intrusive holder

- **连带修复**：已挂在 `docs/已知bug.md` #1 的"freeze() 报 Some intrusive holders were not registered"。
- **范围**：`launcher/mirage-launch` 启动管线（敏感区）。
- **改动点**：
  - native backend（DeferredRegister.setNativeBackend lambda）在 `Registry.register(reg, id, value)` 之后，主动 `unregisteredIntrusiveHolders.remove(value)`——精准清掉本条目对应的 intrusive holder，不再靠 freeze 前暴力 clear 整张表。
  - freeze 前的兜底从无脑 `clear()` 改为：先遍历三个 registry，若仍有残留则**打印数量 + 残留类名**，再 clear——mod 自己 new Block(props.setId) 但没调 Registry.register 的情况会在日志里显形，不静默吞。
- **根因**：MC 26.x `Properties.setId(ResourceKey)` 在 Block/Item 构造时创建 intrusive `Holder.Reference` 塞进 `unregisteredIntrusiveHolders`；`Registry.register()` 在 unfreeze 的 registry 上不总是把它移走，freeze() 检查时 map 非空就抛错。
- **验证方式**：`gradle :launcher:mirage-launch:build` BUILD SUCCESSFUL。**人工冒烟待补**：双击 `启动 26.2-mirage.bat`，确认 mdk-example 能进主菜单，且日志里 freeze 前不打印"bug#1 兜底"残留行。
