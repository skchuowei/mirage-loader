# MG-Errors.md — 错误分级规范

> 版本：**v0.1**（初版，2026-10-11 起 3 天内冻结）
> 维护：A1（MG-Spec）
> 铁律（对齐项目总纲 §六.4）：**禁止静默失败**。任何异常、缺失、冲突都必须落到本文件的某一级，并以规定格式输出。

---

## 1. 三级定义

| 级别 | 标识 | 行为 | 可见性 |
|---|---|---|---|
| 可忽略 | `WARN-LOW` | 记录，继续加载，不打扰用户 | 仅写日志文件 |
| 警告 | `WARN` | 记录，继续加载；汇总进周报 | 日志 + A9 周报提示 |
| 致命 | `FATAL` | 终止加载，输出可操作错误信息 | 日志 + 控制台 + 崩溃报告 |

---

## 2. 判定原则

### 2.1 WARN-LOW（可忽略）

**判定原则**：该问题**不影响任何已声明功能的正确性**，且只在"可选、边缘、环境差异"场景发生。即使完全忽略，模组的核心行为依然成立。

同时满足以下三条才可定此级：

1. 缺失/失败的对象是 `OPTIONAL` 依赖、客户端专属资源（在服务端环境）、可选降级点（`CAPTURE_FAIL_SOFT`）；
2. 不改变注册表内容、不改变事件派发语义；
3. 有明确、安全的默认行为兜底。

### 2.2 WARN（警告）

**判定原则**：功能可能**部分受损或存在不确定性**，但启动仍可进行；用户应当知情，以便决定是否排查。

典型边界特征：

- 动态描述缺失（A3 沙箱超时），只能靠静态描述重放 → 行为可能与原加载器有出入；
- A6 报告了 `UnsupportedApiFeature`，但不影响启动路径；
- 资源文件存在但引用悬空（lang key 缺失、模型 JSON 指向不存在的纹理）；
- OPTIONAL 依赖缺失导致某功能分支被禁用。

### 2.3 FATAL（致命）

**判定原则**：以下任一成立即 FATAL——

1. 必需依赖缺失 / 版本范围不满足 / INCOMPATIBLE 命中；
2. 依赖环、加载图无法拓扑排序；
3. 注册表 ID 冲突（同 modid 重复 或 跨 modid 冲突）；
4. 字节码变换打不到目标（方法/字段/类不存在），且不是 `SOFT` 降级点；
5. entrypoint 构造抛异常；
6. `mod.mirage.json` schema 非法、`mirageSpecVersion` 过新、命名空间与他人冲突；
7. 任何"静默跳过即可启动，但结果语义无法预测"的场景——**宁可崩，不可糊**。

---

## 3. 错误码规则

格式：`<级别首字母>-<领域>-<三位序号>`

- 级别首字母：`L`（WARN-LOW）/ `W`（WARN）/ `F`（FATAL）
- 领域：`DEP` 依赖、`PARSE` 描述解析、`XFORM` 字节码变换、`REG` 注册表、`EVT` 事件、`RES` 资源、`INIT` 模组初始化、`ENV` 运行时环境

示例：`F-DEP-001`（致命-依赖-第 1 号）、`L-RES-003`。错误码一经分配不复用；废弃码保留不重用。

---

## 4. 日志输出格式

单行结构：

```
[LEVEL] [ISO8601时间] [阶段/modId] 错误码: 消息 | key1=value1 key2=value2
```

字段：

- `LEVEL`：`WARN-LOW` / `WARN` / `FATAL`
- 时间：ISO8601 带时区，如 `2026-10-11T14:03:21.445+08:00`
- 阶段：对齐 MG-Lifecycle.md 的 S1–S7（发现/解析/转换/注册表/事件总线/模组初始化/加载完成）
- `modId`：相关模组，无归属写 `runtime`
- 消息：一句说清"发生了什么"
- `|` 后：可序列化上下文键值对，**FATAL 必须包含至少一个"可操作信息"**（缺失的依赖名、冲突双方 id、目标方法签名等）

示例：

```
[WARN-LOW] [2026-10-11T14:01:02.110+08:00] [发现/examplemod] L-DEP-002: 可选依赖 jei-integration 未找到，相关功能将禁用 | modId=examplemod optionalDep=jei-integration
[WARN] [2026-10-11T14:02:45.830+08:00] [解析/betterfarming] W-XFORM-004: A3 沙箱报告超时，将仅用静态描述重放，行为可能与原加载器有差异 | modId=betterfarming timeoutMs=30000
[FATAL] [2026-10-11T14:03:21.445+08:00] [注册表/examplemod] F-REG-001: 注册表 minecraft:block 中 ID "examplemod:ruby_ore" 与模组 "othermod" 冲突 | existingOwner=othermod incomingMod=examplemod registry=minecraft:block entryId=examplemod:ruby_ore
```

## 5. 各级典型例子（≥5 个/级）

### 5.1 WARN-LOW 示例

| # | 场景 | 说明 |
|---|---|---|
| 1 | OPTIONAL 依赖缺失（`jei-integration` 未安装） | 功能降级，继续 |
| 2 | 专用服务器上加载了 CLIENT 侧模组 | 豁免客户端依赖，按服务端行为跑 |
| 3 | Mixin `locals=CAPTURE_FAIL_SOFT` 捕获局部变量失败 | 该注入继续，局部变量按默认值 |
| 4 | 资源包内多余/未引用的文件 | 无害文件，忽略 |
| 5 | 过时 API 使用（`@Deprecated`） | 记录，不影响运行 |
| 6 | mods 目录里的非模组文件（如 `.zip` 备份） | 跳过，不报错 |

### 5.2 WARN 示例

| # | 场景 | 说明 |
|---|---|---|
| 1 | A3 沙箱报告超时 / 沙箱进程崩溃 | 仅静态描述重放，行为可能漂移，进周报 |
| 2 | A6 报告 `UnsupportedApiFeature`（某 Fabric API 未实现） | 模组可启动，但该调用点运行时会再报错 |
| 3 | lang 文件缺失某 key / 模型 JSON 引用了不存在的纹理 | 显示层面降级（英文/紫黑方块） |
| 4 | RECOMMENDED 依赖缺失 | 周报提示用户"建议装 X" |
| 5 | 同 modid 不同 sha1 的两个 jar 同时存在 | 保留先发现者，另一个提示用户清理 |
| 6 | 描述合并时静态与动态字段矛盾（已按动态优先） | 记录冲突点，便于 A8 对比测试 |

### 5.3 FATAL 示例

| # | 场景 | 错误码 | 可操作信息必须包含 |
|---|---|---|---|
| 1 | REQUIRED 依赖缺失（如 `mirage-api >=1.0.0` 未安装） | `F-DEP-001` | 缺失依赖名 + 需要的版本范围 + 哪些模组要它 |
| 2 | 依赖环：A→B→C→A | `F-DEP-003` | 完整环路径 |
| 3 | 注册表 ID 跨 modid 冲突 | `F-REG-001` | 先注册者 + 冲突 entryId |
| 4 | Mixin 注入目标方法不存在（硬要求） | `F-XFORM-002` | 目标类 + 方法签名 + 哪个 mixin 类 |
| 5 | entrypoint 构造抛异常 | `F-INIT-001` | entrypoint 类名 + 异常堆栈首行 |
| 6 | `mod.mirage.json` schema 非法 / `mirageSpecVersion` 过新 | `F-PARSE-001` | 具体字段路径 + 期望 vs 实际 |
| 7 | 两个模组声明同一命名空间 | `F-RES-001` | 冲突双方 modid |
| 8 | INCOMPATIBLE 模组同时安装 | `F-DEP-005` | 冲突双方 |

## 6. FATAL 错误信息的"可操作性"要求

FATAL 上报时，消息正文必须按以下模板组织，方便用户直接行动：

```
加载失败：<一句话原因>
  ↳ 相关模组：modId（版本）
  ↳ 冲突/缺失对象：<具体名字>
  ↳ 建议动作：<删除 X / 安装 Y / 升级 MG 到 ≥z / 检查 Z>
```

- 禁止只输出堆栈不输出解释。
- 禁止"发生未知错误"这类无信息消息——模块自己都没定位清楚 = 设计 bug，先报 A1。

## 7. 与其他模块的衔接

- **A4 运行时**：实现 `ErrorSink`（见 MG-Interfaces.md §11），负责落盘日志文件 `logs/mirage-YYYY-MM-DD.log` 与崩溃报告 `crash-reports/`。
- **A8 QA**：CI 中断条件 = 出现任一 FATAL；WARN 计数纳入兼容率统计；WARN-LOW 不中断。
- **A9 报告**：每周报汇总 WARN 条目（按 modId 分组），不堆 WARN-LOW（只给总数）。
- **分级争议**：模块拿不准定级时，**从高定级**（按 WARN 处理而不是 WARN-LOW），并在该条目上下文里打 `escalation=true`，A1 在下个迭代回收裁决。
