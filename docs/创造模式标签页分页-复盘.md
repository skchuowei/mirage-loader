# 创造模式标签页分页功能 · 复盘

> 日期：2026-10-17
> 涉及文件：`core/mirage-loader/src/main/java/io/mirage/loader/MirageDebug.java`
> 状态：**修复方向正确，但未在游戏中真正验证过——改完即崩，崩因是 fat jar 打包问题，与分页逻辑本身无关**

---

## 1. 原始 Bug 现象

mod 注册了创造模式标签栏（CreativeModeTab），当标签数量超过一行可显示范围时，原版 MC 会显示翻页切换按钮。

**Bug**：可以翻阅，但翻页后标签切换会全部重叠在第 1 号位（第 0 列）。

---

## 2. 根因分析（方向是对的）

`MirageDebug.java` 里两个方法配合出错：

### 2.1 `getDisplayColumn()`

反射读取原版 `CreativeModeTab.displayAllTabs` 的列号。**反射失败时 catch 返回 0**——把"反射失败/不可见"和"第 0 列"混为一谈。

```java
// 旧代码（错误）
private int getDisplayColumn(CreativeModeTab tab) {
    try {
        // 反射读列号
    } catch (Exception e) {
        return 0;  // ← 错：0 是合法列号，不能当"未知/不可见"用
    }
}
```

### 2.2 `remapColumn()`

```java
// 旧代码（错误）
private int remapColumn(int c) {
    if (c < 0) c = 0;  // ← 把负列号强制归零
    return c;
}
```

### 2.3 结果

不在当前页的 tab（反射拿不到列号 → 返回 0）全部被映射到第 0 列，叠在一起。

---

## 3. 修复方案（改了 3 行）

| 位置 | 旧值 | 新值 | 语义 |
|---|---|---|---|
| `getDisplayColumn()` catch 分支 | `return 0;` | `return -1;` | -1 = 不可见，不是第 0 列 |
| `remapColumn()` | `if (c < 0) c = 0;` | `if (c < 0) return 0;` | 不可见 tab 不参与重映射（shouldDrawTab 已过滤） |

---

## 4. 为什么"改完就崩"——真正的教训

> **分页逻辑本身没有错。崩溃是 fat jar 打包流程被我搞坏了，不是分页代码导致的。**

| # | 坑 | 后果 |
|---|---|---|
| 1 | **没有备份可用的 fat jar** | 改完部署崩溃后，想回滚只能重新编译打包，但此时打包流程已经坏了 |
| 2 | **手动打包 fat jar 太脆弱** | 没有 shadow 插件，靠 `jar cf` + 手动解压依赖 jar。漏了 `META-INF/services/` 里的 `IMixinServiceBootstrap`、`asm-util`、签名文件 BOM，一连串问题 |
| 3 | **崩溃后排查方向跑偏** | 一开始以为是分页 bug 本身导致 `StackOverflowError`，回滚 MirageDebug.java 后崩溃依旧，才发现是 fat jar 打包问题 |
| 4 | **改完没验证编译产物** | 直接热部署 `.class` 进 fat jar，没有先跑一次完整启动验证 |
| 5 | **清 gradle 缓存是核弹操作** | `Remove-Item ~/.gradle/caches` 后，所有依赖重新下载，且手动打包时容易漏依赖 |
| 6 | **`transformer is null` 排查绕了大弯** | 花了很久才发现是 fat jar 里缺 `META-INF/services/org.spongepowered.asm.service.IMixinService` 服务注册文件，导致 `ServiceLoader` 找不到 `MirageMixinService` |

## 5. 给下一个 AI 的交接要点

### 5.1 分页逻辑本身

**修复方向是对的**，但从头到尾**没有在游戏里真正验证过**——改完就崩，崩了好几天，最后修的是 fat jar 打包问题，不是分页问题。

重新做时需要：

1. **先备份可用的 fat jar**：`copy mirage-launch-0.1.0.jar mirage-launch-0.1.0.jar.bak`，改坏了能秒回滚
2. **用 shadow 插件自动打 fat jar**，不要手动 `jar cf`
3. **分页逻辑单独抽成可测的纯函数**：输入 `(allTabs, currentPage, tabsPerRow)` → 输出 `(visibleTabs, remappedColumns)`，先跑单元测试再织入游戏
4. **反射读取原版字段时，失败要返回特殊值（-1）而不是 0**——0 是合法列号，不能当"未知"用
5. **每次改完只部署一个 `.class` 进去验证**，不要重新打包整个 fat jar

### 5.2 fat jar 打包注意事项

当前 fat jar 是手动打包的（没有 shadow 插件），必须包含：

| 内容 | 位置 |
|---|---|
| 所有模块的 class 文件 | `api/mirage-api`、`core/mirage-loader`、`core/mirage-mixin`、`core/mirage-eventbus`、`launcher/mirage-launch` 的 `build/classes/java/main` |
| 服务注册文件 | `META-INF/services/org.spongepowered.asm.service.IMixinService`（内容：`io.mirage.mixin.MirageMixinService`） |
| 全局属性服务 | `META-INF/services/org.spongepowered.asm.service.IGlobalPropertyService`（内容：`io.mirage.mixin.MirageGlobalProperties`） |
| 清空 bootstrap 服务 | `META-INF/services/org.spongepowered.asm.service.IMixinServiceBootstrap`（内容：空，不要让 LaunchWrapper/ModLauncher bootstrap 加载） |
| ASM 依赖 | asm、asm-commons、asm-tree、asm-analysis、asm-util（9.9） |
| Mixin 依赖 | org.spongepowered:mixin:0.8.7 |
| Gson 依赖 | com.google.code.gson:gson:2.11.0 |
| 签名文件 | 删除所有 `META-INF/*.SF`、`*.DSA`、`*.RSA`、`MANIFEST.MF`（多 jar 合并后签名必失效） |
