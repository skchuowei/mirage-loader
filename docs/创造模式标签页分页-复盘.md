# 创造模式标签页分页功能 · 复盘

> 日期：2026-10-18 更新
> 涉及文件：`core/mirage-loader/src/main/java/io/mirage/loader/MirageDebug.java`、`core/mirage-loader/src/main/java/io/mirage/loader/MirageTransformer.java`
> 状态：**真正根因定位——不是分页逻辑错，是 ASM 字节码偏移硬写和 MC 26.2 实际方法结构不匹配。下一步改用 Mixin 重写。**

---

## 1. 原始 Bug 现象

mod 注册了创造模式标签栏（CreativeModeTab），当标签数量超过一行可显示范围时，原版 MC 会显示翻页切换按钮。

**Bug**：可以翻阅，但翻页后标签切换会全部重叠在第 1 号位（第 0 列）。

---

## 2. 问题定位历程（三次转向）

### 第一次定位（错误）：归因于 fat jar 打包

最早以为是手动打包 fat jar 漏了依赖导致崩溃。修了 Mixin 服务加载管线（commit `88c2275`）后游戏能启动到主菜单，但分页功能依然不对。

### 第二次定位（半对）：归因于 MirageDebug 语义 bug

复盘时认为根因是：
- `getDisplayColumn()` 反射失败返回 0，把"未知"和"第 0 列"混淆
- `remapColumn()` 把负列号强制归零

修复后热替换 class 部署，发现标签全部消失（回退逻辑写错），修正后又全部叠在第 0 列，控制台持续抛 `Not bootstrapped` 异常。

### 第三次定位（真正根因）：ASM 字节码偏移不匹配

查 NeoForge 源码确认 `column`/`row` 是 `private final` 字段后，把反射从调用 getter 改成直接读字段，异常依然存在。

**最终定位**：问题根本不在 `MirageDebug` 逻辑，是 `MirageTransformer` 里硬写的 ASM 字节码偏移和 MC 26.2 里 `CreativeModeInventoryScreen` 方法的实际字节码结构完全不匹配：

| 织入点 | 硬写的偏移 | 实际情况 |
|---|---|---|
| `extractTabButton()` 开头 | POP 原版 column 栈顶，替换成 `remapColumn(tab)` 的返回值 | POP 错了栈位置——原版方法里此时栈上不止 column 一个值 |
| `getTabX()` 返回值 | IRETURN 替换成 `remapTabX(tab)` | 方法签名/局部变量表已经变了，硬替换返回值会搞断执行流 |
| `istore 7` | 假设 column 存在局部变量槽 7 | MC 26.2 重构后局部变量表布局变了，槽 7 存的不是 column |

**结果**：ASM 织入把原版方法执行流搞断了，原版自己抛异常，标签画不出来。

---

## 3. 为什么硬写字节码偏移是错的

| 问题 | 后果 |
|---|---|
| **脆弱** | MC 小版本更新方法结构变了（局部变量表、栈帧、指令顺序），织入全坏 |
| **不可读** | POP/istore/ireturn 硬编码偏移，没人知道对应的是哪个变量 |
| **难调试** | 织入错了不会报"织入失败"，而是原版方法跑一半抛异常，堆栈指向原版 class |
| **和 Mixin 重复造轮子** | 项目已经有完整可用的 Mixin 系统（commit `88c2275`），却还用底层 ASM 硬织入 |

---

## 4. 正确做法：改用 Mixin

项目本身已经有完整可用的 Mixin 系统（`core/mirage-mixin` 模块），应该用 Mixin 来实现分页：

| 原来 ASM 硬织入 | 改成 Mixin |
|---|---|
| 硬写偏移 POP 栈顶 | `@Inject` 在方法开头/结尾注入 |
| 硬替换 IRETURN | `@ModifyReturnValue` 修改返回值 |
| 硬写局部变量槽号 | `@Local` 捕获局部变量，按名字引用 |
| 手动字节码偏移计算 | Mixin 自动匹配方法签名，版本变了编译时就报错 |

---

## 5. 其他加载器怎么做的（参考）

### 原版 MC 26.2
- `column`（0-6）和 `row`（TOP/BOTTOM）是 `CreativeModeTab` 的 final 字段，创建时固定
- 纹理数组只有 7 个位置（`tab_top_selected_1` 到 `_7`）
- 超过 7 个 tab 全部 `clamp` 到第 7 个位置，叠在一起
- **没有分页功能**

### NeoForge 26.2
- 自己写了 `CreativeTabsScreenPage` 类，每页 10 个位置（顶部 5 + 底部 5）
- **不是翻页，是重排**：mod tab 放前面，原版 tab 放后面
- 通过 `CreativeModeTabRegistry` 维护有向图拓扑排序
- 用 mixin/AT patch 原版 Screen

### Fabric
- 完全不做分页，只提供 `getTabsOnPage()` 查询接口
- mod 多了自己想办法（比如 JEI 做自己的标签页管理）

### 结论
MG 的"翻页"方案是最彻底的（NeoForge 只是重排，Fabric 不管），但**实现方式应该从 ASM 硬织入改成 Mixin**。

## 6. 给下一个 AI 的交接要点

### 6.1 不要做的事
- ❌ 不要在 `MirageTransformer` 里继续硬写字节码偏移
- ❌ 不要手动打 fat jar（用 shadow 插件或只热替换单个 class）
- ❌ 不要清 gradle 缓存（核弹操作）

### 6.2 应该做的事
1. **用 Mixin 重写分页逻辑**：
   - `@Inject(method = "extractTabButton", at = @At("HEAD"))` —— 判断 shouldDrawTab，不可见直接 return
   - `@ModifyReturnValue(method = "getTabX")` —— 替换 X 坐标
   - `@Inject(method = "extractBackground", at = @At("TAIL"))` —— 画翻页按钮
   - `@Inject(method = "mouseClicked", at = @At("HEAD"))` —— 处理翻页按钮点击
2. **分页状态（currentPage、totalPages）放在 Mixin 类或独立类里**，不要塞进 MirageDebug
3. **反射读 `column` 字段时，直接读 private final 字段**（NeoForge 也是这么做的），不要调 getter
4. **先备份 fat jar 再改**，改坏了 1 秒回滚

### 6.3 关键路径

| 项 | 路径 |
|---|---|
| Mixin 模块 | `core/mirage-mixin/src/main/java/io/mirage/mixin/` |
