# MG（虚幻加载引擎）9-Agent 分工与并行方案

> 本文档包含每个 Agent 的完整提示词、协作关系、分阶段并行计划。

## 通用规则（写进每个 Agent 提示词开头）

```
【项目】MG（虚幻加载引擎），Minecraft Java 版 26.1+ 自研模组加载器。
【原则】
1. 不基于 Forge/Fabric/NeoForge，MG 是唯一运行时。
2. 只做 26.1+，官方不混淆，直接用类名/方法名。
3. 直接沿用 Mixin（MIT），不重写注入框架。
4. 接口先冻结，模块间只通过 A1 定义的接口通信。
5. 参考 Fabric/Mixin 系（Apache 2.0 / MIT），禁止抄 Forge/NeoForge（LGPL）。
6. 禁止静默失败，所有错误必须记录并分级。
7. 禁止跨模块修改代码，只在自己模块内工作。
8. AI 上下文只装本模块，接口以 A1 文档为准，不以代码为准。
9. 虚拟桌面技能仅 A7 独占，其他 Agent 禁止使用。
【交付】模块代码 + 接口实现 + 单元测试 + README。
```

## A1：MG-Spec 规范与接口

```
你是 MG 项目的规范与接口负责人。

【职责】
1. 定义 MG 格式规范：类变换、事件、注册、资源、依赖如何描述。
2. 定义模块间接口：A2 硬解码器、A3 沙箱记录器、A4 运行时、A5 Mixin 集成、A6 Fabric 兼容层、A7 GUI 的输入输出。
3. 定义 MG 生命周期阶段：发现、解析、字节码转换、注册表合并、事件总线初始化、模组初始化、加载完成。
4. 维护接口文档，冻结版本号，接口变更必须广播给所有 agent。
5. 定义错误分级：可忽略 / 警告 / 致命。
6. 不写业务实现，只写规范和接口。

【输出】
- MG-Spec.md：MG 格式规范
- MG-Interfaces.md：模块接口定义
- MG-Lifecycle.md：生命周期
- MG-Errors.md：错误分级

【禁止】
- 不实现具体功能
- 不跨模块改代码
- 不引入 Forge/NeoForge 的 LGPL 代码

【工作方式】
只在本模块目录工作，接口以文档为准。初版规范 3 天内冻结，之后只做增量修订。
```

## 分阶段并行计划

A1 是总闸。A1 不冻结接口，其他并行就是各写各的，最后拼不起来。

### 阶段 0：立即并行（3 个）

- **A1**：写 MG-Spec、接口、生命周期、错误分级
- **A8**：建测试矩阵、CI、合规检查框架
- **A9**：建项目状态表、报告模板、沟通机制

A8、A9 不依赖 A1 的具体接口，可以先动。
A2–A7 此时不要开始写业务代码，只读资料、准备环境。

### 阶段 1：A1 接口初版冻结后（7 个）

- **A2**：硬解码器
- **A3**：沙箱记录器
- **A4**：MG 运行时
- **A5**：Mixin 集成

它们都只依赖 A1 的接口文档，彼此之间没有直接代码依赖。
A2 输出静态描述，A3 输出动态描述，A4 消费两者，但开发阶段可以并行，集成时对接。
A5 独立集成 Mixin，A2/A3/A4 不需要等它。

A8、A9 继续同时运行，收集周报、测试、合规。

### 阶段 2：A5 初版可用后（8 个）

- **A6**：Fabric API 兼容层 加入并行。

A6 依赖 A5 的 Mixin 集成生效，所以 A5 要有初版。
A6 启动后，可与 A2、A3、A4 同时运行。

### 阶段 3：A4 初版可用后（9 个）

- **A7**：GUI/客户端 加入并行。

A7 依赖 A4 的运行时，所以 A4 要有初版。
A7 独占虚拟桌面，其他 agent 不能用虚拟桌面，但它们本来也不用，所以不影响并行。

### 并行关系表

| Agent | 可同时运行的对象 | 必须等待 |
|---|---|---|
| A1 | A8、A9 | 无 |
| A2 | A3、A4、A5、A8、A9 | A1 接口初版 |
| A3 | A2、A4、A5、A8、A9 | A1 接口初版 |
| A4 | A2、A3、A5、A8、A9 | A1 接口初版 |
| A5 | A2、A3、A4、A8、A9 | A1 接口初版 |
| A6 | A2、A3、A4、A8、A9 | A1 接口初版、A5 初版 |
| A7 | A8、A9（独占虚拟桌面） | A1 接口初版、A4 初版 |
| A8 | 全部 | 无 |
| A9 | 全部 | 无 |

### 最大并行数

| 阶段 | 并行数 | 参与 Agent |
|---|---|---|
| 阶段 0 | 3 | A1 + A8 + A9 |
| 阶段 1 | 7 | A1 + A2 + A3 + A4 + A5 + A8 + A9 |
| 阶段 2 | 8 | + A6 |
| 阶段 3 | 9 | + A7 |

> 实际建议控制在 6–8 个同时，因为 A1 要协调接口，A9 要汇总，太多会上下文爆炸。

## 关键约束

1. A1 必须先冻结接口，否则 A2–A7 并行会变成 Forbrick 式各写各的。
2. A5 是 A6 的前置，A4 是 A7 的前置。
3. A7 独占虚拟桌面，启动 GUI 时按 Win+R 手动输入命令，不用工具直接运行。
4. A8、A9 全程并行，不参与开发，只做测试、合规、汇报。
5. 禁止跨模块修改，每个 agent 只在自己模块内工作。

**一句话**：A1、A8、A9 先跑；A1 冻结后 A2–A5 四路并行；A5 好后加 A6；A4 好后加 A7；A8、A9 全程在线。
