# 双窗口风格 1:1 统一 + 交接期消息泵保活

> 关联：用户实机截图两张（2026-11-07 10:16）；上一轮 `9330fd7`（主窗口改抗锯齿灰度字）；`ForgeStyleLayout` 注释「唯一基准是早期窗口」；已知限制 #24（交接须等渲染线程退出）。

## 目标

让启动过程的两个窗口（GLFW 早期窗口 / 原生 MC 窗口）**文字字形 1:1 同源**，以第一张截图（早期窗口）为准；并消除窗口交接期间 Windows 判定的「未响应」。

**可验证标准**：① 离线回归能断言「两个窗口读的是同一个字体资源」；② 离线回归能断言「交接等待期间消息泵被反复调用且不会阻塞满 5 秒」；③ 用户双击 bat 实机看到两窗口字形一致、交接不卡（GUI 规则，AI 不自行启动）。

## 现状分析

**风格不同**：两张截图配色、进度条、布局完全相同（同用 `ForgeStyleLayout` + `LoadProgress.View`），唯一差异是文字字形。

| | 早期窗口（第一张） | 主窗口（第二张） |
|---|---|---|
| 类 | `MirageEarlyWindow` + `EarlyFont` | `ForgeStyleOverlay` + `MirageDebug` |
| ASCII 字体 | `/Monocraft.ttf`，STB 打包 24px 图集 | 上一轮 `9330fd7` 换成 `Segoe UI` / `Microsoft YaHei UI` 系统 UI 无衬线 |
| CJK 字体 | `C:/Windows/Fonts/msyh.ttc` | `pickCjkFont` → `Microsoft YaHei`（同源，但 AWT 家族解析） |
| 渲染 | GL 纹理 quad，线性灰度 alpha | AWT 光栅化 → 4 档覆盖率 → 与背景预混 RGB → `fill` 矩形 |

早期窗口用的是细等宽字形，主窗口是加粗圆润无衬线，观感跳跃。`ForgeStyleLayout` 已注明「唯一基准是早期窗口」，因此**以早期窗口为准、把同源字形接到主窗口**，早期窗口保持不动。

**为什么不能把主窗口改成 STB 通道**：LoadingOverlay 期字形图集未就绪，`gge.text()` 静默无字（已知限制 #30 / C19），GL 纹理通道也不在 MC 的 GuiGraphics 里；渲染线程碰 AWT 会占住 GLFW 消息泵（C60）。所以主窗口只能继续留在「AWT 预光栅化 + fill 矩形」通道，改的是**字体源**，不是渲染通道。

**交接未响应**：`MirageEarlyWindow.handoff()` 依次 `renderLock.tryAcquire(3, SECONDS)`、`renderTask.cancel`、`scheduler.shutdownNow()` + `awaitTermination(2, SECONDS)`，合计最多 5 秒。`handedOff = true` 后渲染线程不再 `glfwPollEvents()`，而交接线程在这两次阻塞等待里也不抽窗口消息——正好踩中 Windows 判定「未响应」的阈值。代码注释里也记着「实测 S7 阶段里交接占了好几秒」。

## 每处改动要点

1. `ForgeStyleOverlay.pickFont(px)`：`Font.createFont(Font.TRUETYPE_FONT, getResourceAsStream("/Monocraft.ttf")).deriveFont(px)`。资源由 `launcher/mirage-launch/src/main/resources/` 提供，fat jar 里在根路径；离线回归把同一份文件复制到 classes 根。加载失败时回退 `Consolas → MONOSPACED`（保留可出字，不因字体缺失整屏无字）。
2. `pickCjkFont(px)`：先试 `Font.createFont(..., new File("C:/Windows/Fonts/msyh.ttc"))`（与 `EarlyFont.findCjkFont()` 同一文件），失败再走原有家族名候选。这样两边 CJK 也真正同源，而不是「同家族不同文件」。
3. `HandoffPump.await`：纯逻辑，循环 `{ ready? → return true; 超时? → return false; pump.run(); parkNanos(1ms); }`。把「等待期间持续抽消息」写成可测的签名约束，而不是散在 handoff 里的隐式约定。
4. `handoff()`：`tryAcquire` 与 `awaitTermination` 换成两次 `HandoffPump.await`；`awaitTermination` 的中断语义保留（超时后仍继续交接，但打 warn 记录）；`glfwMakeContextCurrent` 仍在等渲染线程退出之后，避免 GL 上下文竞态。
5. 回归：`verify_forgestyle_text.ps1` 的 `glyphs/glypharea/glyphmixed/glyphlevels/overflow` 与文字带断言按新字形重新取基线；新增守卫要求 `ForgeStyleOverlay` 出现 `/Monocraft.ttf`、`EarlyFont` 构造实参含 `/Monocraft.ttf`（两边同一字符串）。`verify_handoff_pump.ps1` 变异点挑「断言不跟随的量」：删掉 `pump.run()`、把超时改回 3000/2000、把 handoff 改回裸 `tryAcquire(3, SECONDS)`。

## 回归测试影响面

- 换字体源会改变所有字形的 advance 与墨迹盒，**`verify_forgestyle_text.ps1` 里按块中心判定文字带的断言需要重新取基线**；「内存文字居中」「版本号右对齐」是按 `textWidth` 算的，理论上仍成立，但要实跑确认。
- 抗锯齿多档断言（`glyphmixed` / `glyphlevels`）有风险：Monocraft 是像素字形，AWT 10px 下若接近二值会让断言变红。若发生，先确认是「真回到点阵字」还是「档位阈值需要调」，不直接改断言放水。
- `verify_earlyfont_stb.ps1`（早期窗口字表）、`verify_loadprogress.ps1`（逻辑模型）零侵入，但按规则复跑确认。
- `gradle build` 与 `fatJar` 必须重打；fat jar 里要确认 `Monocraft.ttf` 存在且 `HandoffPump.class` 在包内。
