# MSR P2 · 单次运行原则（根治双跑）

> 关联：`docs/plans/2026-10-25_msr-roadmap.md`（P2 原始条目）、`docs/plans/2026-10-31_msr-p1.md`（P1 前置）、`docs/plans/2026-10-31_AG-总计划重梳理.md`（T5.3/T5.5）

## 目标

让 mod 构造函数**只跑一遍**：录制不再是"额外跑一次构造函数"，而变成真实加载的副产品。

P1 已止血（进程不死、数据不带半成品），但 roadmap 缺陷 2/5 原样存在：
构造跑两遍（沙盒 + 真实），副作用双发；`recorded` 数据无消费方，纯空转。

## 可验证标准（四条全过才算 done）

1. **首启零 fake pass**：toml 声明了完整 `neoforge` + `minecraft` 版本区间的 mod，首启**不出现** `[Sandbox] 开始录制` 且不实例化沙盒类加载器；缺区间的 mod 仍按需录制。
2. **被动捕获产出**：真实加载窗口内收集到该 mod 的 API 触达 / 事件类型 / DeferredRegister 计数，写进 `.mid-cache` 且 `source=passive`、`complete=true`。
3. **崩溃不留半成品**：写缓存走 `tmp + ATOMIC_MOVE`；模拟"写到一半被杀"（残留 `.tmp`）后，`lookup` 不得把半成品当有效条目，且无 `.json` 解析失败。
4. **消费方真的在消耗**：测试 mod 在 `@Mod` 构造里查 `FMLLoader.versionInfo().neoForgeVersion()` → 收到按 MID 约定的版本（而非 `null`/`NoClassDefFoundError`）；二启对同一 mod 产出 diff 行（有变化写 `mid-diff.log`，无变化一行 debug 日志）。

## 现状核对（改前，逐条对代码）

| roadmap 缺陷 | 现状 |
|---|---|
| 2 · 构造跑两遍 | `ModDiscoverer` 里 `needRecord = sandboxEnabled && (recorded == null \|\| force)` → 只要缓存没有 `recorded` 就录，首启**全部** neo mod 各跑一遍构造 |
| 4 · fake 手工枚举 | 不动（P3 消化）；但"仅在缺数据时才录"缩小了它的暴露面 |
| 5 · `recorded` 无消费方 | 全仓无任何读取 `recorded.*` 的代码（只有 `ModDiscoverer` 判空）。`LoaderVersionMasquerade` 是第一个消费方 |
| 7 · `recorded_loader_version` 与静态解析重复 | `SandboxRecorder` 只是把 `detected.neoForgeVersionRange` / `mcVersionRange` 抄进 `recorded`，**录制过程不产生任何新的版本信息** → 这两字段对"伪装"毫无价值，伪装必须直接读 `Detected` |

关键结论：**fake pass 从来不产生版本信息**，它只产生 `touched_apis` / `registered_events` / `deferred_register_count`。
所以"按需化"的判据只能是"缺版本区间"（roadmap 指定）而不是"缺 MID"；真实价值在于把这些采集搬到真实加载里。

## 设计

### 1. fake pass 按需化 —— `RecordingPolicy`（纯函数，可单测）

```java
enum Reason { OFF, FORCE, MISSING_RANGES, CACHED, COOLDOWN }
static Decision decide(String mode, Detected d, Recorded prev);
```

| 输入 | 决策 | 理由 |
|---|---|---|
| `mode=off` | 不录 | OFF |
| `mode=force` | 录 | FORCE |
| `prev == null` 且缺 `neoForgeVersionRange` 或 `mcVersionRange` | 录 | MISSING_RANGES |
| `prev == null` 且区间完整 | **不录** | CACHED（完整区间已够伪装，touched 数据由被动捕获补） |
| `prev != null` 且 `prev.failed` / 空数据 | 不录 | COOLDOWN（同样的 fake 表面重录结果一样；表面变了 `fakeVersion` 校对会先让缓存失效） |

日志：每个跳过打一行 debug（附理由），整轮一行 debug 汇总 `fake pass: N 次 / 跳过 M（区间完整）/ 被动 K`。
**首启"零 fake pass 日志"的判据**：`[Sandbox] 开始录制` 出现次数 = 0（debug 汇总行仍然有，说明统计口径）。

### 2. 被动捕获 —— `PassiveRecorder`

窗口按 mod 开合（S6 串行，静态 volatile 当前窗口，窗口外所有 hook 是 no-op）：

```java
PassiveRecorder.begin(modId, jar);     // S6 每个 mod 之前
...
PassiveRecorder.end();                 // mod 之后：返回 Result(apis, events, drCount, complete)
```

挂点（全部自有代码，不插桩 MC 字节码）：

| 挂点 | 记什么 |
|---|---|
| `io.mirage.api.registry.DeferredRegister.create(...)` | `api: DeferredRegister.create` + `dr++` |
| `io.mirage.api.registry.DeferredRegister.register(name, supplier)` | `api: DeferredRegister.register` |
| `net.neoforged.neoforge.registries.DeferredRegister.create*(...)` | `api: NeoDeferredRegister.create*` + `dr++` |
| `io.mirage.eventbus.EventBus.register(Object)` | 扫 `@SubscribeEvent` 首参 → events；`api: EventBus.register` |
| `io.mirage.neoforge.runtime.NeoEventBusImpl.register / addListener` | 同上（NeoForge mod 的实际总线） |
| `net.neoforged.fml.ModLoadingContext.registerConfig` | `api: ModLoadingContext.registerConfig` |

跨模块解耦：api 侧新增 `io.mirage.api.hook.PassiveHooks`（三个 `volatile Consumer/Runnable`，默认 null = no-op），
loader 侧 `PassiveRecorder` 在第一次 `begin` 时装上实现。依赖方向不变（api ← eventbus/compat/loader）。

`complete` 判据：该 mod 的所有入口（main + side）都没有进 `failures` 列表。只有 `complete=true` 才写盘。

### 3. 写盘 —— `MidCache.storePassive`

- `Recorded.source`：`"sandbox"` / `"passive"` / `"sandbox+passive"`；`Recorded.complete`。
- 合并策略：已有 sandbox 数据 → 并集 apis/events，`drCount = max`，`source="sandbox+passive"`；
  **无变化不写盘**（避免每次启动都改文件）。
- 原子写：`<name>.json.tmp` → `Files.move(..., ATOMIC_MOVE)`；不支持时退化为 `REPLACE_EXISTING` 并 warn。
- **半成品防线**：`lookup` 只认 `.json`（`.tmp` 天然不被读）；`.json` 解析失败仍走删除重来。

### 4. 消费方 —— `LoaderVersionMasquerade` + 二启 diff

**版本伪装**：`api` 侧 `io.mirage.api.version.VersionMasks`（`ThreadLocal` 当前 modId → 该 mod 应看到的版本串），
compat 侧新增 stub `net.neoforged.fml.loading.{FMLLoader,VersionInfo}`，`versionInfo()` 读 `VersionMasks`。

版本选择算法（`LoaderVersionMasquerade.pick(range, fallback)`，纯函数）：
- 区间为空 → fallback（当前 MC / 兼容层版本）；
- 当前版本落在区间内 → 报当前版本（不伪装，最诚实）；
- 否则取区间里离当前最近的端点（`[26.1,27)` + 当前 26.2 → 26.2 在区间内；`[26.1.0.1,26.1.1]` + 当前 26.2 → 报 26.1.1）；
- 解析不了的格式 → fallback + 一行 warn（不猜）。

**二启 diff**：`PassiveRecorder` 结束时拿磁盘上的旧 `recorded` 与本轮比较，
有差异 → 追加写 `.mid-cache/<mcVer>/mid-diff.log`（时间戳 + mod + `+apis/-apis/+events/-events/dr 旧→新`）；
无差异 → 一行 debug。

## 明确不做（本轮）

- 不动 `MirageClassLoader`（工作区有 Fabric F1 的 WIP，混提风险）→ **不采"mod 自己加载了哪些类"**，
  被动捕获只有 API 级触达，比沙盒的 touched_apis 窄（如实记入文档，不假装等价）；
- 不动 fake 表面语义、不动 P3 的实例化录制；
- 不做运行时"版本冲突 FATAL 判定"（版本区间目前全仓无消费方，伪装只解决"报什么"，不新增拒绝路径）。

## 风险与回滚

- **S6 挂点**改的是真实游戏路径，纯 JVM 只能验"钩子函数行为"，验不了"S6 是否按预期调用"→ 实机冒烟必须做（用户双击 bat）。
  所有挂点用 `try/catch (Throwable)` 包住，失败只降级（不写缓存），绝不阻断 mod 初始化。
- **缓存大面积重写一次**：首启会从"只有 detected"升级到"detected + passive"，属预期。
- 回滚 = `git revert <本轮 commit>`；`.mid-cache` 新增字段全可空，旧文件仍可读。
