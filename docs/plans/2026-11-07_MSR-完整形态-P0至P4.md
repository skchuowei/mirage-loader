# 完整 MSR（P0–P4 全阶段收口）：让录制器对真实 NeoForge mod 真正产出数据

> 关联：`docs/plans/2026-10-25_msr-roadmap.md`（P0–P4 路线图）、`docs/plans/2026-10-31_msr-p1.md`、
> `docs/plans/2026-10-31_msr-p2.md`（P1/P2 实施记录）、`docs/plans/2026-11-07_NeoForge大规模测试前收口.md`（N0–N4）；
> 本轮取证：2026-11-07 15:0x，探针 `Probe`/`Probe2` 跑真实 26.2 NeoForge mod（JEI 30.48.0.244 / Jade 26.2.10 / Cloth Config 26.2.155）。

## 目标

把 MSR 从「在自造夹具上跑得通」推进到「**完整形态**：对真实 NeoForge mod 有行为级可用产出」。

用户裁决（2026-11-07）：**要完整 MSR**（含 P3 注入器深录），且**本轮顺带把缺失的 stub 补齐**。

**可验证标准（四道门禁，按顺序过）**

- **门禁 A（M1–M4，离线可验）**：对 `mods-library/neoforge/` 的 3 个真实 mod 跑一条离线命令后：
  ① 依赖段正确解析出 `type="required"` 的依赖（JEI → `mezz_config`）；
  ② 录制失败原因**可分类**（`missing_fake` / `stub_incomplete` / `ctor_failed` 三选一），不再只有裸 CNFE；
  ③ `touched_apis` 对真实 mod 非空，且与该 mod 的常量池引用对账有明确覆盖率口径；
  ④ 全程不启动 Minecraft（纯 JVM）。
- **门禁 B（stub 补齐，链接期）**：N0 扫描器对 JEI 的缺失数从 **81 → ≤ 20**；Cloth Config 5 → 0；FerriteCore 3 → 0。
- **门禁 C（P3 注入器，实机）**：`mirage-recorder-agent` 在**真实 NeoForge 客户端实例**里跑一次，产出行为级 MID（注册表新增 id 清单 + 事件订阅清单），与空基线实例求差后输出可读 IR。
- **门禁 D（P4 fake 自动化）**：构建期能从任意真实 mod jar 自动算出 fake 缺口并生成缺口类，生成物可被 fake pass 成功加载。

## 现状分析

### 1. 决定性证据：MSR 对真实 mod **零产出**

探针直接调 `SandboxRecorder.record()` 跑真实 mod（2026-11-07 实测）：

| mod | 结果 | apis | events | error |
|---|---|---|---|---|
| JEI 30.48.0.244 | **failed** | 0 | 0 | `NoClassDefFoundError: net/neoforged/api/distmarker/Dist` |
| Jade 26.2.10 | **failed** | 0 | 0 | `NoClassDefFoundError: net/minecraft/core/HolderLookup$Provider`（fake 表面未覆盖） |

fake 表面源码只有 **19 个类**（`core/mirage-loader/src/sandbox/java/`），而 JEI 引用 **92 个** `net/neoforged/*`（N0 实测），缺 81 ⇒ **fake pass 在真实 mod 上 100% 失败**。

### 2. 缓存实况印证

`<gameDir>/.mid-cache/26.2/` 实有 4 个条目：
- `expore+*.json`（spec 0.4）：`recorded.source=passive`，6 apis、6 次 DeferredRegister、0 事件 ⇒ **只有自建夹具**录得出东西；
- `jei+*.json` / `jade+*.json`（spec **0.1**，老 schema）：`recorded = null`、`neoForgeVersionRange = null`。

### 3. 根因分四层

**(a) fake 表面是手工枚举的固定集（roadmap 缺陷 #4）**
`SandboxClassLoader.FAKE_PREFIX = "mirage/sandbox-fake/"` 下只有 19 个类，`findFakeClass` 找不到就抛 CNFE。真实 mod 引用几百个类 ⇒ 必然失败。

**(b) `NeoForgeModDetector.parseDependencies` 只认 `mandatory=`，不认真实 toml 的 `type="required"`**
JEI 的真实依赖段：

```toml
[[dependencies.jei]]
    modId="mezz_config"
    type="required"
    versionRange="[0.6.3,1.0.0)"
```

解析器 switch 只有 `case "mandatory"`，`type` 落进 `default -> {}` 被丢弃 ⇒ `curMandatory` 恒 `false` ⇒ **`depends` 永远为空**（探针实测三个真实 mod 的 `depends={}`）。连带后果：
- 真实 mod 之间的**拓扑排序约束完全失效**（JEI 依赖 `mezz_config`）；
- Jade / Cloth Config 只有 `neoforge` 区间、没有 `minecraft` 区间 ⇒ 被判 `MISSING_RANGES` ⇒ **每次启动白跑一次必失败的 fake pass**。

**(c) 被动捕获覆盖面窄**
`PassiveHooks` 挂点只在自有代码里（`DeferredRegister.create/register`、`IEventBus.register/addListener`、`ModLoadingContext.registerConfig`）。mod 直接调 MC 原版方法看不到 ⇒ 对真实 mod 只能拿到极少量数据。

**(d) stub 面缺口 81 个（N0 实测）**
JEI 缺的 81 个里，绝大多数是 `net.neoforged.neoforge.client.*` 客户端事件（`ScreenEvent.*` 18 个、`ClientTickEvent.*`、`RenderTooltipEvent.*` 等）——**这些正是 fake pass 与真实加载都会炸的地方**。

### 4. 与 N0–N4 的关系

本轮**接管 N1 的 stub 补齐部分**（用户裁决「本轮顺带把 stub 补了」），N1 的其余部分（AT 应用、`[[mixins]]`、`@EventBusSubscriber`）留给 N2。
MSR 的 fake pass **直接复用**本轮补出的 stub 字节码 ⇒ 两边一份代码、零重复维护。

## 每处改动要点

### M1 · 依赖段认 `type="required"`

- switch 增加 `case "type" -> curType = v;`；判定：**required = `type` 为 `required` 或（`type` 缺失且 `mandatory=true`）**；optional 同理。
- **兼容双写法**：自建夹具（`neop0test`）用旧式 `mandatory=true`，真实 mod 用 `type="required"`，两者都要工作。
- `Detected.depends` 语义不变（只收 required）⇒ `DependencySorter` 拓扑排序自动受益，**不需要改 sorter**。
- 平台依赖（neoforge/minecraft）区间记录不受影响（`PLATFORM_MODS` 分支先行）。
- 边界：解析器要**先收完整段再判定**（`type` 可能在 `modId` 前后）。

### M2 · fake pass 复用 compat stub（核心）

- `SandboxClassLoader` 增加构造参数 `FakeProvider provider`（可空），**保留旧签名重载**（provider=null）以免打断既有夹具。
- `findFakeClass` 顺序：① `mirage/sandbox-fake/` 资源；② `provider.findFakeBytes(name)`；③ 都没有 ⇒ CNFE（保持现消息格式，既有断言不破）。
- `CompatFakeProvider` **只读**：用 `ClassLoader.getResourceAsStream(name.replace('.','/') + ".class")` 读 compat 模块**已编译的 stub 字节码**，不碰 compat 源码 ⇒ 本轮补的 stub 自动成为 MSR 的 fake。
- 风险：stub 静态初始化副作用（如 `NeoForge.EVENT_BUS`）会在沙盒里连带初始化 ⇒ 在 `SandboxRecorder.StateSnapshot` 里补记静态字段副作用（无法恢复，只能记录）。

### M3 · 失败原因三分类

- `NoClassDefFoundError` / `ClassNotFoundException` 且缺失类名在 fake 覆盖域（`net.neoforged.*` / `net.minecraft.*`）⇒ `error = "missing_fake: <类名>"`；
- `NoSuchMethodError` / `UnsupportedOperationException` ⇒ `error = "stub_incomplete: <类>#<方法>"`；
- 其它 ⇒ `error = "ctor_failed: <原描述>"`。
- 日志用**不同前缀**（`[Sandbox] fake 缺口` / `[Sandbox] stub 不足` / `[Sandbox] 构造失败`），一眼可分。
- `FakeGapAnalyzer` 的缺口清单**就是 N1' 的输入**，一份数据两处用。

### M4 · 录制判据不再浪费

- `force` ⇒ 录；区间完整 ⇒ 不录（被动捕获接手）；**区间不完整 ⇒ 不再无条件录**：
  - 「从未录过」⇒ 录一次（诊断价值）；
  - 「上次录过且失败原因是 `missing_fake`/`stub_incomplete`」⇒ **不再重录**（重录还是同样结果，纯浪费）；
  - 「上次录过且是 `ctor_failed`」⇒ 可重录一次（mod 可能已修）。
- 消掉 Jade / Cloth Config 每次启动的必失败录制。

### N1' · clean-room 补 stub（用户裁决本轮做）

- **签名来源**：本地 `loader-11.0.16.jar` / `mergetool-2.0.7-api.jar` / `bus-8.0.5.jar` / `neoforge-26.2.0.90-universal.jar`，用 `javap -p` 提取**签名**（不抄实现）。
- **实现原则**（沿用 compat 层既定原则）：
  - 只做**最小可用**实现；未知方法一律抛 `UnsupportedOperationException` 带类名+方法名，**不返回编造值**；
  - 路径/环境类（`FMLPaths`/`FMLEnvironment`/`FMLServerDist`）的值**由加载器注入**，不写死相对路径（bug #4 的教训）；
  - 事件类：**类定义 + post 调用点 + 构建期注入校验**三件套齐（AGENTS 技术注意事项第 7 节：只建类不 post = 假覆盖）。
- 优先级（按 JEI 缺口清单 + 加载路径关键度）：
  1. **链接期必需**（不补就直接 CNFE）：`Dist`/`EnvType`、`ModContainer`、`ModList`、`FMLPaths`、`FMLEnvironment`、`LoadingModList`、`IModBusEvent`、`JarContents`、`ModInfo`、`NeoForge`、`NeoForgeMod`、`Tags`、`IModFileInfo`/`IModInfo`/`ModFileScanData`/`IConfigurable`、`IModFile`；
  2. **客户端事件族**（JEI 缺口主体）：`ClientTickEvent`、`ClientPlayerNetworkEvent`、`ClientChatReceivedEvent`、`RegisterKeyMappingsEvent`、`RenderTooltipEvent`、`ScreenEvent`（18 个嵌套类）、`RecipesReceivedEvent`、`AddClientReloadListenersEvent`、`ClientStoppingEvent`、`RegisterClientCommandsEvent`、`RegisterClientTooltipComponentFactoriesEvent`；
  3. **客户端支撑类**：`ClientHooks`、`ClientTooltipFlag`、`IConfigScreenFactory`、`IClientItemExtensions`、`IClientMobEffectExtensions`、`KeyConflictContext`/`IKeyConflictContext`/`KeyModifier`、`FluidTintSource`、`ClientPacketDistributor`；
  4. **其余**：`server/ServerAboutToStartEvent`/`ServerStartedEvent`、`OnDatapackSyncEvent`、`IPayloadContext`、`HandlerThread`、`IItemExtension`/`TooltipFlagExtension`、`BrewingRecipe`、`FluidUtil`、`FluidStack`/`FluidSlotDisplay` 等。
- **P3 agent 依赖**：`ServerAboutToStartEvent` 是 P3 的「录完即退」触发点 ⇒ 必须补，且要有 post 调用点。

### P3 · 注入器深录（client 形态）

| 组件 | 设计 |
|---|---|
| 实例形态 | **一次性 client 实例**（仓库外 `%TEMP%\mirage-msr-<rand>`）：`minecraft-client-patched-26.2.0.90.jar` + `neoforge-26.2.0.90-universal.jar` + loader/bus/mergetool + natives；**不用 dedicated server**（网络限制 + client 覆盖面更广） |
| 启动 | `-javaagent:mirage-recorder-agent.jar` + `-Dmirage.msr.out=<dir>`；mod 放入实例 `mods/` |
| Agent | `premain` → `Instrumentation.addTransformer(new RecorderTransformer(), true)`；**不进 MG fat jar**（构建期工具，不进用户启动路径） |
| 插桩点 | ① `MappedRegistry.register`（退出前 dump 全量 id，与基线求差）② `EventBus.addListener` / `@SubscribeEvent` 扫描入口 ③ `ModConfig` 加载 ④ `SimpleChannel` 注册 |
| 归属 | `DeferredRegister` 自带 modId 为主，栈回溯找 mod jar 类兜底；分不清的标「归属未知」，**不猜** |
| 基线 | 空 mods 实例跑一次存注册表快照 + 事件列表 |
| 隔离 | 一次性 `userdir`（世界/配置/日志全在内），跑完即弃；**断网运行**（`--offline`） |
| 产物 | 观测日志 → 组装 IR（`mod.mirage.json` 风格，带实例 NeoForge/MC 版本标签） |
| 退出 | `ServerAboutToStartEvent` 之后 `System.exit(0)`（client 形态改成「客户端进入主菜单后退出」，用 agent 自检点判定） |
| 成本 | 一次性冷启动 10–30s（固定上限，比 fake pass 最坏 N×2s 更省） |

### P4 · fake 自动化

- 构建期从真实 jar 生成缺口 fake：常量池预检（扫 mod jar 引用的 `net.*` 类 ∩ fake 覆盖）算缺口 → **只生成缺口类**。
- 暗坑：enum 的 `<clinit>` 不能剥（常量是 static final 字段，剥了全 null）；签名闭包会拖传递依赖 ⇒ 只做缺口不做全量；enum/注解/接口进白名单保留原样或保留 clinit。

## 合规边界（条件必填）

涉及 `modules/mirage-neoforge-compat/`、`modules/mirage-msr-agent/`、`refs/neoforge/`。
NeoForge 为 LGPL 2.1：本计划只做**行为观察 / 接口签名枚举 / clean-room 实现**，**不抄其实现代码**。
- stub 实现依据是 `javap` 提取的**签名**（方法名/参数/返回类型）+ 本项目自己的设计，不是 NeoForge 的字节码逻辑。
- `CompatFakeProvider` 读取的是**本项目自己的 clean-room stub** 编译产物，**不是** NeoForge 的字节码 —— 不构成复制第三方实现。
- P3 agent **只读** NeoForge/MC 的类做插桩与基线对照，不修改它们的字节码，不把它们的实现带入 MG。
- `THIRD_PARTY_NOTICES.md` 的授权口径不变。

## 回滚方案

- 阶段独立提交（M1–M4 / N1' / P3 / P4），回滚按 `git revert <commit>`。
- M2（fake 复用 compat stub）带 kill switch：`-Dmirage.msr.fakeprovider=off` 退回「只用固定 fake 表面」的老行为。
- N1' 新增 stub 是**纯新增**，回滚即删文件；已有 stub 不改语义。
- P3 agent 是独立模块，回滚不影响 MG 主链路（它根本不在 fat jar 里）。
- 每次部署前备份 fat jar（`.bak-YYYYMMDD-msr`）；回滚后按规则 6 写回退报告，说明连带撤掉的内容。
- `RecordingPolicy` 判据变更若引发既有回归，`verify_msr_p2.ps1` 的相关断言可**临时标注「判据已变，见 M4」**而不是删掉——但必须在更新日志写明。
