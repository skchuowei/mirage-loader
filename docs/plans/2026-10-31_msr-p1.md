# MSR P1 · 沙盒录制器进程内加固

> 关联：`docs/plans/2026-10-25_msr-roadmap.md`（P1 原始条目）、`docs/plans/2026-10-17_sandbox-neo.md`（MSR 设计）、`docs/plans/2026-10-18_sandbox-neo-impl.md`（P0 落地）、`docs/plans/2026-10-31_AG-总计划重梳理.md`（T5.3）

## 目标

把 MSR-neo 从"能跑的 fake pass 预检器"推到"进程内不会把 launcher 带走、数据不带半成品"的状态，**不 fork 子 JVM**。

可验证标准（五条全过才算 done）：

1. 测试 mod 在构造里 `System.exit(7)` → 沙盒返回 `failed=true, error="SandboxKillException: exit(7)"`，**launcher 进程存活**；
2. 测试 mod 构造死循环 → 约 2 s 后 `failed=true, error="timeout", incomplete=true`，且 `touched_apis` 为空（半成品不入库）；
3. 测试 mod 改动 `Locale` / `TimeZone` / `System.setProperty` 后抛异常 → 录制返回后三项全部恢复，mod 自己的属性被清除、既有属性保留；
4. 常规 mod（`@Mod` + `DeferredRegister` + 自带 mixin 配置）录制成功且 `deferred_register_count ≥ 1`；
5. fake 表面未覆盖的类 → 诚实失败（`error` 含 `fake 表面未覆盖`），不崩、不静默。

## 前置条件与阻塞项

- 无硬阻塞：P0（`SandboxRecorder` / `SandboxClassLoader` / 20 个 fake 表面类 / `MidCache.recorded`）已在 HEAD。
- 工作区有 15 改 + 20 未跟踪的旧 WIP（Fabric F1、早期窗口、ForgeStyle 加载界面）。本轮只碰 `sandbox/`、`MidCache.java`、`ModDiscoverer.java`（后两者的 WIP 差异是 MirageLog 接入，已提交 `3a8cb1b`，不冲突），**不提交那批 WIP**。
- 与 AG 总计划分期有交叉：总计划把 MSR P1 排在 Phase 5（Phase 4 发布之后）。本轮由用户直接指令"继续 MSR"提前执行；P1 只依赖内核，不依赖已发布的 api，提前做不产生返工。

## 现状分析

`SandboxRecorder.record()` 现在的实际行为：

| 缺陷（roadmap 编号） | 代码现状 |
|---|---|
| 1 · `System.exit` 杀进程 | mod 类由继承的 `URLClassLoader.findClass` 定义，字节码原样执行 → `System.exit` 直接走 JVM 退出钩子，launcher 一起死 |
| 2 · 双跑副作用 | P2 才治（本轮不动 `ModDiscoverer` 的"是否录制"决策） |
| 3 · 超时不 interrupt、半成品入库 | `t.join(2000)` 超时只置 `failed=true, error="timeout"`，线程带 `setDaemon(true)` 继续跑到进程退出；`finally` 里照常把 `sink.apis()` 写进 `recorded` |
| 4 · fake 手工枚举 | 设计问题，P3 消化，本轮不动 |
| 6 · 缓存 key 无 fake 版本维度 | `.mid-cache` 只校对 `agVersion / jarSha256 / mcVersion`；fake 表面改动后老 `recorded` 照命中 |
| — · 全局态被污染 | mod 构造里 `Locale.setDefault` / `TimeZone.setDefault` / `System.setProperty` 录完不还原，污染的是 launcher 自己的进程 |

关键实现约束（踩坑结论，来自 roadmap"修正记录"与本次读码）：

- **改写挂点必须是 `findClass`**，不是 `defineClass`：非 fake 包走 `super.loadClass` → `URLClassLoader.findClass`，mod 类由继承实现定义，不过我们自己的 `defineClass`。
- 改写只换调用、不改栈形状：`System.exit(I)V` → 静态 `(I)V`；`Runtime.exit|halt(I)V` → 静态 `(Ljava/lang/Runtime;I)V`（接收者已在栈上，正好当第 0 参）。栈映射帧完全不变，`ClassWriter(cr, 0)` 即可，**不需要** `COMPUTE_FRAMES`（项目史上 ASM 改写丢帧导致 Mixin 二次转换失败的坑，见 AGENTS 技术注意第 9 条）。
- 我们接管 `findClass` 后，`defineClass` 的默认保护域会丢 `CodeSource`，而少数 mod 会 `getProtectionDomain().getCodeSource().getLocation()` 定位自己的 jar → 必须显式构造 `ProtectionDomain`（指向 mod jar）。

## 每处改动要点

### 1. `SandboxKillException`

```java
public final class SandboxKillException extends Error {
    private final int exitCode;
    public SandboxKillException(int exitCode) {
        super("exit(" + exitCode + ")", null, false, false);  // 不填栈：录制只关心退出码
    }
}
```

继承 `Error`：mod 里随处可见的 `catch (Exception e)` 不能把"退出"吞掉。

### 2. `SandboxGuard`

三个静态方法，全部 `throw new SandboxKillException(code)`。`Runtime` 参数不用（只为吃掉栈上的接收者）。

### 3. `SandboxBytecodeGuard.rewrite(byte[] bytes, int[] hits)`

- 探测：`ClassReader.accept` 一个无 delegate 的 `ClassVisitor`，命中即抛私有 `Stop`（早停信号，关栈）→ 无命中返回**原数组**（不动字节码，零风险）。
- 命中则 `new ClassWriter(cr, 0)` + 同样规则的 `visitMethodInsn` 替换：
  - `INVOKESTATIC java/lang/System.exit (I)V` → `INVOKESTATIC SandboxGuard.exit (I)V`
  - `INVOKEVIRTUAL|INVOKEINTERFACE java/lang/Runtime.exit (I)V` → `INVOKESTATIC SandboxGuard.exitRuntime (Ljava/lang/Runtime;I)V`
  - `INVOKEVIRTUAL|INVOKEINTERFACE java/lang/Runtime.halt (I)V` → `INVOKESTATIC SandboxGuard.halt (Ljava/lang/Runtime;I)V`

### 4. `SandboxClassLoader`

新增：

```java
@Override
protected Class<?> findClass(String name) throws ClassNotFoundException {
    URL res = findResource(name.replace('.', '/') + ".class");
    if (res == null) throw new ClassNotFoundException(name);
    byte[] bytes = readAll(res);
    byte[] out = bytes;
    try { out = SandboxBytecodeGuard.rewrite(bytes, hits); }
    catch (Throwable t) { /* 如实 warn，退回原字节：类必须能加载 */ }
    return defineClass(name, out, 0, out.length, domainOf(res));
}
```

`domainOf(res)`：从 `jar:file:/x.jar!/a/B.class` 截到 `jar:file:/x.jar!/` 作 `CodeSource`，`new ProtectionDomain(cs, null, this, null)`，保住 `getCodeSource().getLocation()`。

### 5. `SandboxRecorder`

- 录制前 `SandboxState.snapshot()`：`Locale.getDefault()`、`TimeZone.getDefault()`、`System.getProperties()` 的**拷贝**。
- `finally` 里 `state.restore()`：先 `Locale.setDefault` / `TimeZone.setDefault`，再把当前 properties 里**快照没有的键删掉**、快照里的键**逐个写回**。
- 超时：`t.join(TIMEOUT_MS)` 后 `t.interrupt()`，置 `failed=true, incomplete=true, error="timeout"`。
- `finally` 里：`incomplete` → `touched_apis`/`registered_events` 置空、`deferred_register_count=0`（半成品一律不入库）；否则照常收集。
- `fakeVersion()`：一次性扫描 fat jar 内 `mirage/sandbox-fake/**`，按 `name:size:crc` 排序后 SHA-256 取前 16 位；同时产出 `fakePackages`（替换原 `listFakePackages` 的单独扫描）。dev（class 目录）场景回退 `"dev"`，扫不到回退 `"none"`。

### 6. `MidCache` / `ModDiscoverer`

- `Entry.fakeVersion`，`specVersion="0.3"`；`lookup` 只在 `e.recorded != null` 时比对（检测结果本身不依赖 fake 表面，不该被连坐失效）。
- `Recorded.incomplete` 落盘字段（用于诊断"为什么这个 mod 每次都在重录"）。
- `ModDiscoverer`：`recorded.incomplete` → `cache.store(jar, neo, null)` + warn。

## 回归测试影响面

- **可能被打破**：所有走沙盒的 NeoForge mod 的类加载路径都换了（`findClass` 从继承实现改为自实现）。风险点：`CodeSource`/`ProtectionDomain`（已显式构造）、`definePackage`（未做，原实现也没做）、并行加载（`URLClassLoader` 默认非并行，原样）。
- **缓存一次性失效**：老 `.mid-cache` 条目没有 `fakeVersion`，`recorded != null` 的会全部重录一次（N × ≤2 s）。这是预期行为，不是 bug。
- **`SandboxKillException` 是 Error**：mod 若 `catch (Throwable)` 仍能吞掉 → 该路径本轮不承诺（记入已知限制）。
- mdk-example / 启动冒烟步骤不变；`scripts/verify_sandbox_neo.ps1`（读真实 `.mid-cache`）不变，仍可跑。

## 验证步骤

1. `gradle :core:mirage-loader:compileJava`（先确认基线可编译）。
2. 改完 `gradle :launcher:mirage-launch:fatJar`（**不能用 `build`**，它会把 fat jar 覆盖成 67 KB 瘦 jar）。
3. `powershell -ExecutionPolicy Bypass -File .\scripts\verify_msr_p1.ps1` → 期望全绿（断言数 ≈ 20）。
4. 变异检验：把 `SandboxClassLoader.findClass` 里的改写临时去掉（`out = bytes`），重跑脚本 → `CASE-EXIT` 必须让整个 java 进程退出码非 0 / 无 `HARNESS-DONE`；改回来再跑。
5. 实机冒烟：部署 fat jar 后**遵守虚拟桌面规则，由用户双击 `..\启动 26.2-mirage.bat`**，AI 不直接拉 java；启动后查 `..\logs\latest.log` 有无 `[Sandbox]` 异常，`.mid-cache` 里条目是否带 `fakeVersion`。
